# Systems and practice: automated quality control in audiobook and long-form TTS (as of 2026-11-12)

Scope: what working systems check, how they fix failures, the defect taxonomies that production and research use, and the reusable parts. Methods in depth (alignment, pronunciation scoring, prosody, loudness) belong to the other researchers. Activity dates come from the GitHub API on 2026-11-12 (`pushed_at`, latest release), so "last push" means the last commit to any branch.

## 1. Which open-source audiobook and long-form TTS generators have a quality loop, and what does each loop do?

### Takeaway
Only a few open-source tools close the loop automatically, and every one of them uses the same pattern: transcribe the take with Whisper, compute a fuzzy string ratio against the text, and retry with a new seed. Chatterbox-TTS-Extended is the most complete (3 candidates x 3 attempts, pass at ratio 0.85, shortest passing take wins), epub2tts does 2 attempts at fuzz ratio 88, and AllTalk and the VoxCPM2 practitioner gate ended up advisory because false flags on names and numbers were too common. The biggest projects (ebook2audiobook, audiblez, abogen, TTS WebUI, TTS-Audio-Suite) document no recognizer validation at all. None of them reports measured effectiveness, apart from one practitioner blog.

Chatterbox-TTS-Extended (the most complete loop found):
- Each chunk gets `num_candidates_per_chunk` = 3 candidates (range 1 to 10), each with up to `max_attempts_per_candidate` = 3 attempts (range 1 to 10). Seeds are derived per chunk, candidate and attempt from a base seed, and seed 0 means a new random seed each run. [Chatter.py](https://raw.githubusercontent.com/petermg/Chatterbox-TTS-Extended/main/Chatter.py)
- Validation is on by default with faster-whisper "medium". Both strings are normalized (dashes become spaces, all punctuation removed, whitespace collapsed, lowercased), then compared with `difflib.SequenceMatcher(...).ratio()`. The first pass requires a score of at least 0.85, retries require at least 0.95. No jiwer and no word error rate. [Chatter.py](https://raw.githubusercontent.com/petermg/Chatterbox-TTS-Extended/main/Chatter.py)
- Selection: among passing candidates the shortest duration wins. If every candidate fails, `use_longest_transcript_on_fail` (default on) picks the failed candidate with the longest transcript, else the highest similarity. With Whisper bypassed the code takes the first seeded candidate, although the UI help says shortest duration. [Chatter.py](https://raw.githubusercontent.com/petermg/Chatterbox-TTS-Extended/main/Chatter.py)
- Text prep: sentence batching off by default, 300 characters per chunk when on, long sentences split recursively at `; : - ,` then space, short sentences merged with a 20-character minimum. Lowercasing on by default, "J.R.R." becomes "J R R", digits after sentence punctuation (reference numbers) removed, and a user "sound words" replacement list such as `zzz=>sigh`. [Chatter.py](https://raw.githubusercontent.com/petermg/Chatterbox-TTS-Extended/main/Chatter.py), [README](https://github.com/petermg/Chatterbox-TTS-Extended)
- Post-processing, all off by default: Auto-Editor to trim silences, stutters and artifacts (threshold 0.06, margin 0.2 s), RNNoise (pyrnnoise) denoise before Auto-Editor (README claims "almost 100% artifact removal"), and ffmpeg `loudnorm` at I = -24, TP = -2, LRA = 7, or a peak `alimiter` at -2 dB. [Chatter.py](https://raw.githubusercontent.com/petermg/Chatterbox-TTS-Extended/main/Chatter.py)
- The README says faster-whisper "can silently crash" and suggests the original Whisper as a workaround. No effectiveness numbers are published. [README](https://github.com/petermg/Chatterbox-TTS-Extended)

epub2tts:
- `--minratio` defaults to 88 (93 if the flag is given bare, 0 disables), scored with `fuzzywuzzy.fuzz.ratio` against a Whisper "tiny" transcript. `retries = 2` means two attempts in total, each overwriting the same WAV. If both fail the last take is kept and nothing tracks the best. The check is forced off for Kokoro, Edge and OpenAI engines. [epub2tts.py](https://raw.githubusercontent.com/aedocw/epub2tts/main/epub2tts.py)
- Text cleanup replaces `--`, em dashes, semicolons and colons with ", ", converts curly quotes to straight, "&" to "and", removes square brackets, drops EPUB pagebreak, annotation and index elements and footnote links. There is no number-to-words step. The effective chunk is one NLTK sentence. [epub2tts.py](https://raw.githubusercontent.com/aedocw/epub2tts/main/epub2tts.py)
- Audio: 0.6 s silence between XTTS sentences. Chapters are re-joined with `split_on_silence(min_silence_len=1000, silence_thresh=-50)` and 1 s of silence after each piece, plus 2 s at the chapter end. XTTS output gets `noisereduce` (stationary, prop_decrease 0.75), a noise gate at -30 dB, a compressor and a low-shelf boost. [epub2tts.py](https://raw.githubusercontent.com/aedocw/epub2tts/main/epub2tts.py)

AllTalk TTS Generator:
- Whisper (large-v3 default, also tiny, base, medium, turbo) transcribes each chunk, and mismatches show in red. The accuracy setting ranges 90 to 99%, with 96 to 98% suggested for first tests. The maintainer calls it "just a guide" with no way to confirm a 1:1 match. [AllTalk wiki, TTS Generator](https://github.com/erew123/alltalk_tts/wiki/TTS-Generator), [AllTalk issue 506 via search](https://github.aipraa306.workers.dev/erew123/alltalk_tts/issues/506)
- Listed false-positive causes: ellipses and repeated punctuation that TTS does not voice, filler words, and homophones. "Token length issues" are listed as real defects whose fix is smaller chunks, and the best practice is chunks under 250 characters. [AllTalk wiki](https://github.com/erew123/alltalk_tts/wiki/TTS-Generator)

Pandrator:
- An experimental Audio Evaluation predicts MOS with NISQA and either applies a score threshold or keeps the best score from a set number of generations. Whisper (WhisperX) is used for dubbing and XTTS training, not for this check. [Pandrator README via search](https://git.tdem.in/lukaszliniewicz/Pandrator). The current GitHub README (v0.14.3, 2026-11-12) no longer describes this evaluation and talks only of manual take comparison, RVC as a separate step that keeps both takes, and optional LLM text cleanup. [Pandrator on GitHub](https://github.com/lukaszliniewicz/Pandrator)

chatterbox-Audiobook (psdwizzard):
- Volume normalization to RMS targets (audiobook -18 dB, podcast -16, broadcast -23, quiet -20, loud -14) with soft limiting, "Smart Cleanup" to remove silence and artifacts, per-chunk regeneration, `[Character]` tags mapped to voices, a 0.1 s pause per line break. A listed known issue is that short sentences can cause problems. No recognizer check. [README](https://github.com/psdwizzard/chatterbox-Audiobook)

ebook2audiobook, audiblez, abogen, TTS WebUI, TTS-Audio-Suite:
- ebook2audiobook documents no recognizer validation, retries, candidate selection or loudness normalization. It offers SML tags `[pause]`, `[break]`, `[pause:N]`, exposes XTTS temperature, length penalty, repetition penalty, top-k and top-p, and says its optional XTTS text splitting "is known to not be very efficient". [README](https://github.com/DrewThomasson/ebook2audiobook)
- audiblez (Kokoro-82M) has no validation, retries, normalization or pronunciation controls. [README](https://github.com/santinic/audiblez)
- abogen offers LLM text normalization through any OpenAI-compatible model (apostrophes and contractions, context of sentence, paragraph or document), spaCy sentence segmentation so "Mr." and "Dr." don't split sentences, and configurable silence between chapters. No recognizer check. [README](https://github.com/denizsafak/abogen)
- TTS WebUI documents no automatic quality checks. [README](https://github.com/rsxdalv/TTS-WebUI)
- TTS-Audio-Suite supports ChatterBox, F5-TTS, Higgs Audio 2, VibeVoice, IndexTTS-2 and others, with per-segment seed tags such as `[Alice|seed:42]`, pause tags `[pause:1s]`, `[Character]` voice switching that falls back to the narrator with a warning, an experimental phoneme normalizer (espeak IPA), and IndexTTS-2 `<word|pronunciation>` overrides. It has Qwen3-ASR and Granite ASR nodes but documents no validation loop. [README](https://github.com/diodiogod/TTS-Audio-Suite)

IndexTTS2, Higgs Audio, VibeVoice, Orpheus:
- IndexTTS2's web UI segments text at `max_text_tokens_per_segment` = 120 by default and recommends 80 to 200, warning that both too low and too high reduce quality. UI defaults: temperature 0.8, top_p 0.8, top_k 30, repetition_penalty 10.0, num_beams 3, max_mel_tokens 1500, with a warning that too small a value truncates audio. [webui.py](https://raw.githubusercontent.com/index-tts/index-tts/main/webui.py)
- IndexTTS-2.5 (2026-08-10) adds Pinyin, CMU phoneme and Kana replacements for pronunciation, and recommends `emo_alpha` of about 0.6 or lower for natural speech when emotion comes from text. [README](https://github.com/index-tts/index-tts)
- Higgs Audio v2 uses `--chunk_method speaker` for multi-speaker runs, example sampling temperature 0.3, top_p 0.95, top_k 50, a 24 GB GPU. It reports Seed-TTS-eval WER 2.44 and SIM 67.70, but WER 18.88 on its two-speaker conversation set. [README_V2](https://github.com/boson-ai/higgs-audio/blob/main/README_V2.md)
- Microsoft removed the VibeVoice-TTS code on 2025-09-05 after misuse. [microsoft/VibeVoice](https://github.com/microsoft/VibeVoice). The community fork says spontaneous background music cannot be controlled directly and is more likely when the voice prompt contains music or the text has introductory phrases, and that the Large model is more stable. [vibevoice-community fork via search](https://github.com/vibevoice-community/VibeVoice)
- Orpheus-FastAPI splits input over 1,000 characters, joins segments with 50 ms crossfades, and fixes repetition penalty at 1.1. Its README does not describe loop detection. [README](https://github.com/Lex-au/Orpheus-FastAPI). audiobook-creator's README says the Orpheus-TTS-FastAPI server "detects decoding errors and infinite audio loops and retries automatically". [audiobook-creator](https://github.com/prakharsr/audiobook-creator)

A practitioner's gate with numbers (VoxCPM2 narration, blog dated 2026-10-19, updated 2026-11-04):
- mlx-whisper large-v3-turbo transcribes each line. English passes at WER 0.2, Mandarin at toneless-pinyin CER 0.15. An earlier CER 0.1 rule rejected the author's own reference clip at 0.128. A keyword check also flags names and error-prone words even when the line-level score passes. [ai-muninn](https://ai-muninn.com/en/blog/voxcpm2-news-shorts-narration-2080ti)
- False rejections came from proper nouns (NVIDIA heard as NVDA, Nemotron as Memotron) and numbers. Passing each line's names and numbers as Whisper `initial_prompt` moved a 40-line golden set from 25 passed and 16 flagged to 37 passed and 1 flagged, and 85 production clips from 39 to 57 passes (missing-word flags 44 to 16), with 0 real misreads let through in both runs. Qwen3-ASR-1.7B scored 36 of 40. [ai-muninn](https://ai-muninn.com/en/blog/voxcpm2-news-shorts-narration-2080ti)
- Fix policy: a "two-take rule". Only lines with mismatched words get pinyin or CMU respelling tags and a second take, which is used without another check. After the gate killed 4 of 8 shorts that the author judged fine, it moved to a warn-only "trust mode". [ai-muninn](https://ai-muninn.com/en/blog/voxcpm2-news-shorts-narration-2080ti)

### Inferences
- AJ's loop (length guard, Parakeet diff of 3 or more inserted or dropped words, two rounds of new seeds) is already stricter and more automatic than every open-source audiobook tool found. The ideas worth taking are Chatterbox-Extended's tie-breaker (shortest passing take, which penalizes added junk, repeats and long internal pauses), its fallback (keep the take whose transcript is longest when all fail), and the VoxCPM2 gate's step of changing the text (respelling) rather than only the seed on the second try.
- Every tool that used a character-level fuzzy ratio needed a high pass mark (85 to 98%) and still got false flags on names, numbers and punctuation. AJ's word-count diff is less noisy. Biasing the recognizer with the line's names, as the `initial_prompt` result shows, is the most effective false-flag fix reported.
- Pandrator's MOS-based best-of-N is the only open-source selection by a quality predictor found, and it was dropped from the current README, which suggests it was not worth its cost.

### Gaps
- No project publishes how often its check fires or how often a retry fixes the take. The only numbers are the VoxCPM2 blog's.
- I could not confirm that Higgs Audio's long-form script uses repetition-aware sampling or its defaults. The archived README_V2 does not document it.
- ebook2audiobook's source was not read. Its README documents no check, but the code could hold one.
- Chatterbox-TTS-Extended's last push is 2025-08-23, so its loop may not have been updated for Chatterbox's later models.

## 2. What do commercial audiobook QC tools check, what error classes do ACX, Audible and publisher proofing guides use, and what is public about automated checks in commercial auto-narration?

### Takeaway
Commercial proofing (Pozotron, Penguin Random House's Orion QC, Amazon's patent) is the same core idea as AJ's Parakeet diff: transcribe, diff against the manuscript, and flag missed, added, repeated or misread words plus long pauses, with a human deciding. ACX's own automated checks are only signal-level (RMS -23 to -18 dB, peak at most -3 dB, noise floor at most -60 dB, room tone 1 to 5 s). The only commercial TTS loop that is public is ElevenLabs Studio's Auto-Regenerate, which detects mispronunciations and artefacts and regenerates up to two times. The others rely on pronunciation lexicons plus human review.

### Cited Findings

Proofing tools and their error classes:
- Pozotron's proofing tool compares audio with the script and flags missed words, added words, misreads, repeated words, excessive pauses and extraneous sounds. Not every flagged item needs correcting, and humans decide. Pickup packets list the timestamp, the error, a voice match and the sentence to re-record with its context. No accuracy figures are published, and the post says "no system (human or automated) catches everything" (post 2026-03-31). [Pozotron blog](https://blog.pozotron.com/what-is-the-pozotron-proofing-tool), [Pozotron features](https://www.pozotron.com/features)
- A Capterra reviewer says Pozotron's chapter ends and beginnings are sometimes off. [Capterra via search](https://www.capterra.com/p/198395/Pozotron-Studio/)
- Pozotron's description of a human proofer's job lists misreads, omissions and ad-libs, skipped or altered words, character voice consistency (voice, tone, accent), inconsistent or incorrect pronunciation, background noise, distracting breaths, awkward pauses, and Whispersync mismatches with the ebook. [Pozotron blog](https://blog.pozotron.com/what-does-an-audiobook-proofer-do)
- Orion QC (Penguin Random House US, alpha Q3 2021, beta Q1 2022) uses Amazon Transcribe to flag missing content, added or repeated content, misread content and silences over 3 s. Incidental noise and digital glitches were on the roadmap, not supported. It aimed to cut QC from 2 to 3 days to minutes, and its stated hard problem was false positives from normalization, such as a date written as digits versus words. [Bertelsmann tech blog](https://tech.bertelsmann.com/en/blog/articles/orion-qc)
- Amazon patent US10922484 (filed 2018-06-28, granted 2021-02-16) diffs an ASR transcript against the manuscript with punctuation and breaks removed. Wrong, omitted, added, repeated or out-of-order content counts as a "fatal flaw". Mispronounced character names weigh more than mispronounced adjectives, homonym libraries turn a difference into a review item, and an example threshold of five or more wrong words per session triggers a full audit. It also lists low or no volume, background noise, distortion and missing audio sections. A re-recorded section is accepted only if its volume and tone match the surrounding audio. [Google Patents](https://patents.google.com/patent/US10922484)
- I found no evidence that Hindenburg Narrator detects misreads automatically. It syncs the manuscript text to the recording so a click on the text jumps to the audio. [Hindenburg](https://hindenburg.com/products/sectors/audio-book-publishers), [Author Media](https://www.authormedia.com/how-to-record-your-own-audiobook-using-hindenburg-narrator/)

ACX:
- Requirements: each file between -23 and -18 dB RMS, peaks no higher than -3 dB, noise floor no higher than -60 dB RMS, 1 to 5 s of room tone at the start and end with spacing that "must not exceed 5 seconds", 192 kbps or higher CBR 44.1 kHz MP3, at most 120 minutes per file, one chapter per file, consistent levels, tone, noise, spacing and pronunciation across the book, and free of plosives, mic pops, mouse clicks, excessive mouth noise and outtakes. "Unauthorized use of text-to-speech, AI, or automated recordings in ACX titles is prohibited." [ACX help](https://help.acx.com/s/article/acx-audio-submission-requirements)
- ACX's automated Audio Analysis checks RMS, peak, bitrate, bitrate method, sample rate, mixed channels and duplicate files, and ACX says it cannot detect all errors. Audio Lab reports 8 metrics including RMS, peak, bitrate and spacing. [ACX Audio Lab](https://www.acx.com/audiolab), [ACX blog](https://www.acx.com/mp/blog/sound-check-audio-lab-launches-on-acx)
- An Audacity forum thread is titled "A good example of passing ACXCheck, but still producing Junk", which shows that signal checks pass bad performances. [Audacity forum](https://forum.audacityteam.org/t/a-good-example-of-passing-acxcheck-but-still-producing-junk/42138)

A defect checklist for AI narration (vendor post, 2026-08-06, vendor has commercial interest):
- AI artifacts: warbled words, metallic consonants, sudden tone shifts, robotic endings, misread punctuation, repeated phrase rhythm, over-smoothed emotion, overdone emphasis on ordinary words, and edit seams where a regenerated block sounds pasted in. Pause faults: none after chapter titles, or long silences after headings. Cross-chapter drift in voice, accent, speed, style, pronunciation, loudness and room tone. Manuscript-match faults: duplicate paragraphs, repeated PDF headers, broken dialogue, wrong section order. [Narration Box](https://narrationbox.com/blog/acx-rejection-checklist-ai-narrated-audiobooks)

Commercial auto-narration:
- ElevenLabs Studio Auto-Regenerate "checks generated audio for mispronunciations or unwanted audio artefacts" and regenerates up to two times at no extra cost (help article, read through a search snippet because the page answered 403). It went live in Studio around 2024-11-19, with a thumbs-down button to refine its detection. [ElevenLabs help](https://help.elevenlabs.io/hc/en-us/articles/30204568681745-What-is-Auto-Regenerate), [Plushcap summary](https://www.plushcap.com/content/elevenlabs/blog/elevenlabs-elevenlabs-auto-regenerate-is-live-in-studio)
- ElevenLabs audiobooks: the editor scans the manuscript and suggests terms that may need pronunciation rules. Dictionaries apply first-match-wins, phoneme rules work only on English models such as Flash v2, AI character detection "should be treated as a starting point" (limit 150 voices per book), and edits require regenerating affected paragraphs. [ElevenLabs docs](https://elevenlabs.io/docs/eleven-creative/products/audiobooks)
- Google Play Books auto-narration has a "Pronunciation check" list of words that need edits, plays every occurrence of a word, and accepts IPA, a recorded example or an offered alternative. Homographs are fixed by respelling the audio text, and a pronunciation change cannot add emphasis. Publishers can opt in to automatic regeneration when the TTS model improves. [Google Books Partner help](https://support.google.com/books/partner/answer/14182676), [Finalize](https://support.google.com/books/partner/answer/14182661)
- Apple Books digital narration runs a review, and content that misses its quality standards is not published. Apple describes teams of linguists, QC specialists and audio engineers. A review still found awkward pronunciations and flat affect. [Apple partner support via search](https://itunespartner.apple.com/books/support/46-digital-narration), [The Bookseller](https://thebookseller.com/news/apple-books-launches-new-suite-of-ai-narrated-audiobooks)
- DeepZen's managed service is a pronunciation check, a proofing review by DeepZen editors, a customer review and two correction rounds, with a customer pronunciation list. [Ingram](https://www.ingramcontent.com/publishers-blog/grow-your-audiobook-catalogue-quickly-and-cost-effectively-with-deepzen-s-high-quality-ai-audiobook)
- Audible (May 2025) offers managed and self-service AI narration to publishers, with optional human linguistic review. Narrators in its voice-replica beta edit the AI narration for mispronunciations and awkward pacing. [TechCrunch](https://techcrunch.com/2025/05/13/audible-is-expanding-its-ai-narrated-audiobook-library/), [Publishers Weekly](https://www.publishersweekly.com/pw/print/20250519/97756-audible-expands-catalog-with-ai-narration-and-translation-services.html), [TechSpot](https://www.techspot.com/news/104661-audible-inviting-us-based-narrators-train-ai-voices.html)

### Inferences
- The industry taxonomy (union of the sources above): word accuracy (missed, added, repeated, misread, out of order), pronunciation (wrong, inconsistent across occurrences, character names weighted highest), pauses (too long, over 3 s per Orion, missing after headings), noise and glitches (clicks, mouth noise, distortion, artifacts), level problems (too quiet, inconsistent between sections), consistency (character voice, tone, accent, speed, loudness across chapters), seams after a retake, and manuscript match (dropped or duplicated paragraphs, order).
- Two items from this list fit AJ's "automatic fix only" rule and are not in his loop yet: an internal long-pause check (Orion's 3 s rule, applied inside a take) and a retake-seam check (the patent accepts a pickup only if its volume and tone match its neighbors, which maps to comparing a retaken take's loudness and pitch with the takes beside it).
- Pronunciation consistency across occurrences is handled commercially by a lexicon plus listening to every occurrence (Google plays all occurrences at once). The automated analogue is to collect every take containing a given name and compare those segments with each other.

### Gaps
- Pozotron's pricing per finished hour and accuracy are not published on the pages read. Hindenburg's current feature list was not checked beyond its product page.
- How ElevenLabs Auto-Regenerate detects a mispronunciation (ASR, confidence or a learned detector) is not public.
- No public detail on Speechify's checks, or on how Apple or Google detect defects before human review.

## 3. Which evaluation toolkits bundle many per-utterance metrics, and which metrics are practical per take on a CPU?

### Takeaway
VERSA (ESPnet lab, Apache-2.0, v1.1.0 on 2026-09-09) is the toolkit to reuse: it wraps 90+ metrics behind one config, including no-reference MOS predictors (UTMOS, DNSMOS, NISQA with noise and discontinuity dimensions, SIG-MOS), VAD, speaking rate, language ID, several ASR WERs and speaker similarity. Seed-TTS-eval is just WER (Whisper-large-v3) plus WavLM speaker similarity. EmergentTTS-Eval needs a cloud audio-LLM judge, and TTSDS2 scores distributions, not single takes. A 2026 ICML paper warns that selecting takes with one ASR and judging them with the same ASR family inflates the gain 2 to 3 times.

### Cited Findings
- VERSA claims "over 90 evaluation/profiling metrics with 10x variants" in four groups (independent, dependent, non-match, distributional). v1.0 was December 2024 and the latest release is v1.1.0 (2026-09-09). The README says MIT while GitHub reports Apache-2.0. [VERSA README](https://github.com/wavlab-speech/versa), [GitHub API](https://api.github.com/repos/wavlab-speech/versa)
- VERSA no-reference metrics include DNSMOS P.835 and P.808, NISQA (MOS plus noisiness, discontinuity, coloration, loudness), UTMOS and UTMOSv2, Sheet SSQA, ScoreQ, SRMR (reverberation), VAD, speaking rate, language ID, Audiobox Aesthetics (CE, CU, PC, PQ), SIG-MOS (coloration, discontinuity, loudness, reverb, signal, overall), VQScore, WV-MOS, Distill-MOS, an AASIST spoof score, and Qwen2-Audio prompts for pitch, pitch range, speech rate, emotion, clarity and recording quality. Text-paired metrics include `whisper_wer`, `fwhisper_wer`, `owsm_wer`, `nemo_wer`, `hubert_wer`, plus `speaker` similarity and `emo2vec_similarity`. It has no WADA-SNR or clipping detector. [VERSA metric catalog](https://raw.githubusercontent.com/wavlab-speech/versa/main/docs/supported_metrics.md)
- Seed-TTS-eval computes WER with Whisper-large-v3 (English) or Paraformer-zh, and SIM with a WavLM-large speaker verification model, on 1,000 Common Voice English and 2,000 Mandarin samples plus a Mandarin hard-case list. Last push 2024-06-14, no licence on GitHub. [seed-tts-eval](https://github.com/BytedanceSpeech/seed-tts-eval), [GitHub API](https://api.github.com/repos/BytedanceSpeech/seed-tts-eval)
- EmergentTTS-Eval (arXiv 2505.23009, NeurIPS 2025) has 1,645 cases in six categories: Emotions, Paralinguistics, Foreign Words, Syntactic Complexity, Complex Pronunciation and Questions. A large audio-language model judge (Gemini, GPT-4o) scores emotion, prosody, intonation and pronunciation, and its rankings correlate with humans at Spearman 0.76 or higher. Code Apache-2.0, last push 2025-12-09. [arXiv](https://arxiv.org/abs/2505.23009v1), [GitHub API](https://api.github.com/repos/boson-ai/EmergentTTS-Eval-public)
- TTSDS2 scores Generic, Speaker, Prosody and Intelligibility factors (a later version adds Environment) as 2-Wasserstein distances between feature distributions of synthetic and real speech, so it rates a system, not a single take. Latest release 2.1.0 (2025-05-17). [TTSDS2 arXiv](https://arxiv.org/html/2506.19441v1), [Emergent Mind](https://www.emergentmind.com/topics/text-to-speech-distribution-score-2-ttsds2), [GitHub API](https://api.github.com/repos/ttsds/ttsds)
- "Best-of-N TTS Evaluation is Confounded by ASR Family Alignment" (Yu and Kang, KAIST, ICML 2026, arXiv 2607.08256): with F5-TTS on LibriSpeech-PC, verifier rankings reverse across Whisper, wav2vec 2.0 and HuBERT evaluators, and a verifier from the same family as the evaluator recovers 2 to 3 times more of the oracle headroom than a cross-family one. Rank ensembles across families reach 1.61% mean WER at N = 10 with no loss in SIM or UTMOS. The best single verifier moves WER from 2.06% to 1.72% under F5-TTS's own evaluator. [arXiv](https://arxiv.org/abs/2607.08256), [ICML](https://icml.cc/virtual/2026/77342)
- Llasa (arXiv 2502.04128) uses off-the-shelf speech understanding models as verifiers at inference time and reports that more test-time compute raises speaker similarity and lowers WER. [arXiv](https://arxiv.org/abs/2502.04128v2), [summary](https://www.themoonlight.io/review/llasa-scaling-train-time-and-inference-time-compute-for-llama-based-speech-synthesis)

### Inferences
- Practical per take on the laptop or Mac CPU, judging by model families (not measured): UTMOS or DNSMOS (small networks) as a naturalness or noise floor score, NISQA's discontinuity dimension as a glitch detector, VAD for internal silences, speaking rate from the existing Parakeet timestamps, and a speaker-embedding similarity against the cast clip. The Qwen2-Audio metrics and EmergentTTS-Eval's judge are too heavy for a per-take CPU check.
- The ICML 2026 result bears on AJ's retake choice: if Parakeet both flags and picks the retake, the gain is overstated. Checking the chosen retake with a second family (Qwen3-ASR, already in the repo, or Whisper) is the cheap guard.

### Gaps
- Amphion's evaluation module was not read, so its metric list is not recorded here.
- No CPU timing per metric was found in any toolkit's docs. Another researcher may cover it.
- Cloud judge cost per finished hour (for example EmergentTTS-style Gemini judging) was not priced.

## 4. What failure types are reported for LLM-based and codec-based zero-shot TTS in long-form use, with rates, and what is reported for Breeze TTS 2?

### Takeaway
The literature names two catastrophic classes, skips (a run of 10 or more deleted words) and hallucinations (a run of 20 or more substituted or inserted words), and both rise sharply with input length: Qwen3-TTS-1.7B's worst-of-10-seeds WER goes from 5.0% under 500 words to 45.7% at 1,000 to 1,500 words. For Breeze TTS 2 the reports are seed-dependent: tail volume collapse (the last sentence fades, mid band down 7.5 dB) and misreads (each in 1 of 26 seeds in one sweep), segment-to-segment changes in timbre, volume and speed, muffled drift past about 45 s on the experimental depth-decoder quantizations, and output collapse with a misaligned reference transcript. Spontaneous background music (VibeVoice), cut-offs (XTTS) and volume fluctuations (gpt-4o-mini-tts) are reported for other models.

### Cited Findings

Research on long-form failures:
- "Taming Long-form Text-to-Speech" (Wang, Durmus, Orhon, Pacheco, Orhon, arXiv 2609.16989, 2026-09-15) defines a skip as "a contiguous deletion of 10 or more words" and a hallucination as "a contiguous mix of substitutions and insertions of 20 or more words". [arXiv HTML](https://arxiv.org/html/2609.16989)
- Mean and worst-of-10-seed WER by prompt length. Qwen3-TTS-0.6B: under 500 words 2.7/5.4%, 500 to 1,000 words 3.5/6.5%, 1,000 to 1,500 words 4.2/11.2%, 1,500 or more 16.6/35.2%. Qwen3-TTS-1.7B: 2.6/5.0%, 4.5/11.9%, 15.6/45.7%, 29.9/47.8%. VoxCPM2: 2.8/5.4%, 3.4/5.2%, 5.2/16.3% (1,000 to 1,300), 18.1/35.0% (1,300 or more). For VoxCPM2, 15.3% of prompt and seed pairs had a skip or hallucination at 1,000 to 1,300 words and 70% beyond 1,300. [arXiv HTML](https://arxiv.org/html/2609.16989)
- Their detector reads the argmax position of emergent text-audio alignment heads, splits the text into equal token bins and counts generation steps per bin. A skip fires when the reading position passes a bin that got far fewer steps than earlier bins, a hallucination when the position stalls for much longer than a bin normally takes. On a trigger it rolls back to the onset, reseeds, and applies a hard attention mask until generation passes the point, which cut worst-of-10 WER at 1,500 or more words from 35.2% to 3.4% (0.6B). With a 120 s reference, catastrophic generations (WER over 30%) fell from 26% to under 1%. Code is promised on publication. [arXiv](https://arxiv.org/abs/2609.16989), [arXiv HTML](https://arxiv.org/html/2609.16989)
- The same paper's wSIM (speaker similarity over 8 s windows with a 4 s stride, worst window across seeds) exposes short identity switches and distortions that whole-clip similarity averages out. Baseline worst-of-N wSIM was 0.01 with a 120 s reference. [arXiv HTML](https://arxiv.org/html/2609.16989)
- GOAT (EMNLP 2025, arXiv 2508.15442) finds a strong positive correlation between hallucination and model uncertainty, and its post-training cuts CER by over 50% on challenging cases. [arXiv](https://arxiv.org/abs/2508.15442). A search summary of the paper adds that mispronunciations, omissions and unnatural repetitions are more frequent on long or complex sentences. [arXiv PDF via search](https://arxiv.org/pdf/2508.15442)
- A CosyVoice2 paper names "stability hallucinations" as repeated or omitted speech and scores alignment with a Viterbi-based Optimal Alignment Score. It was withdrawn in February 2026 for lack of institutional approval. [arXiv](https://arxiv.org/abs/2509.19852)

Breeze TTS 2 (model by BreezeBlue, weights 2026-08-25, research and non-commercial licence, 3B: T5Gemma2 text encoder, Qwen3 backbone, 15-step depth decoder, codec based on the Qwen3-TTS tokenizer, 24 kHz, English and Mandarin):
- The model card gives no WER, no speaker similarity, no maximum text length and no limitations section. It asks for clean reference audio with an exact transcript and an instruction in the same language as the text, suggests CFG 4 for voice design and voice direction, and writes English vocal events inline in parentheses, such as "(laugh)". [Model card](https://huggingface.co/BreezeBlue/Breeze-TTS-2), [HoppouAI GGUF card](https://huggingface.co/HoppouAI/Breeze-TTS-2.cpp)
- Official SDK defaults reported in an issue: temperature 0.9, top_k 50, top_p 1.0, CFG 1.0, repetition penalty 1.1, at most 1,500 new tokens. In a 26-seed voice-design sweep (seeds 42 to 67) checked with Qwen3-ASR-0.6B and per-band RMS of the tail, one seed showed "tail collapse" (the final sentence fades as if the speaker walks away, mid band 300 to 3,000 Hz down 7.5 dB and high band down 2.6 dB against the body) and one seed misread two words. The reporter says "a seed sweep is required" because the failing seed changes with machine and toolchain. Maintainers blamed the RTX 2080 Ti's missing native BF16 and a reference whose transcript did not match the audio. The case is Mandarin. [breeze-tts issue 14](https://github.com/breezeblue-ai/breeze-tts/issues/14)
- Segment consistency: a user splitting a long text into 6 calls with the same reference and seed 42 heard different timbre and volume between segments, which the same text sent in one call did not show. Another user doing novel narration reports that "the volume and speaking speed fluctuate between different segments". Open as of 2026-10-23. [breeze-tts issue 25](https://github.com/breezeblue-ai/breeze-tts/issues/25)
- Maintainer advice in that thread: keep "reasonably long, complete passages together" within one generation and split only at paragraph or sentence boundaries, since the default limit "theoretically supports about 120 seconds of audio". Keep the reference, transcript and parameters identical, and test without an instruction at `cfg_scale=1` to see whether directions cause the variation. Add 0.2 to 0.3 s of silence between segments and normalize loudness. A fixed seed "does not guarantee consistent speaker identity across different texts". [breeze-tts issue 25](https://github.com/breezeblue-ai/breeze-tts/issues/25)
- BreezeBlue's hosted platform preprocesses each clone reference: noise reduction (falling back to the original if it removes speech), a transcribed and aligned excerpt of up to 30 s cut at sentence or pause boundaries, and loudness normalized to -18 LUFS, reused with its transcript for every generation. In their tests local preprocessing gave consistency comparable to the hosted API but stayed seed-sensitive. [breeze-tts issue 25](https://github.com/breezeblue-ai/breeze-tts/issues/25), [BreezeBlue voice clone guide](https://docs.breezeblue.ai/guides/voice-clone)
- Breeze-TTS-2.cpp: Q8_0 has "no audible loss against F16". The experimental `-dd` quantizations "drift progressively muffled and thin past roughly 45 seconds of continuous generation", a gradual failure "easy to miss on quick tests". At the default CFG of 1 the model "treats a tag as a suggestion" and skips uncommon vocal tags, and CFG 2 to 3 is suggested for vocal events. [HoppouAI GGUF card](https://huggingface.co/HoppouAI/Breeze-TTS-2.cpp)
- Breeze-TTS-2.cpp issue 9: on a Windows machine with a non-UTF-8 code page, `breeze-cli` mangled non-ASCII `--text` silently, giving "a normal-looking WAV, plausible duration" with the wrong speech. Its 8 other issues are not quality reports. Latest release v0.1.7 (2026-11-08) adds a voice-call demo, and v0.1.6 (2026-10-31) made the vocoder about 3 times faster. [Breeze-TTS-2.cpp issues](https://github.com/HoppouAI/Breeze-TTS-2.cpp/issues?q=is%3Aissue), [releases](https://github.com/HoppouAI/Breeze-TTS-2.cpp/releases)
- PyTorch SDK: passing a standard `repetition_penalty` crashed until a 2026-11-02 fix, and n-gram blocking stays unsupported. A Chinese word is mispronounced in all voices (open issue 30). [breeze-tts issue 31](https://github.com/breezeblue-ai/breeze-tts/issues/31), [issues list](https://github.com/breezeblue-ai/breeze-tts/issues)
- The Hugging Face discussions for the model hold no quality-problem titles. [HF discussions](https://huggingface.co/BreezeBlue/Breeze-TTS-2/discussions)

Other models, reported by users:
- VibeVoice: spontaneous background music or sounds, more likely with music in the voice prompt or introductory phrases in the text. [vibevoice-community via search](https://github.com/vibevoice-community/VibeVoice), [The Decoder](https://the-decoder.com/microsofts-vibevoice-is-a-new-ai-podcast-model-that-might-generate-spontaneous-singing/)
- OpenAI gpt-4o-mini-tts community threads are titled "Volume Fluctuations, Silence, Repetition, Distortion" and "Getting TTS hallucinations with long inputs". [Thread 1](https://community.openai.com/t/gpt-4o-mini-tts-issues-volume-fluctuations-silence-repetition-distortion/1150897), [Thread 2](https://community.openai.com/t/getting-tts-hallucinations-with-long-inputs-in-40-mini/1226155)
- XTTS-v2: "the text is sometimes abruptly cut off". [HF discussion](https://huggingface.co/coqui/XTTS-v2/discussions/24). ElevenLabs through Retell: "skipping entire sentences". [Retell community](https://community.retellai.com/t/elevenlabs-skipping-entire-sentences/3590)

### Inferences
- Defect types AJ has not listed that the sources show for this model class: a fade or collapse at the end of a take (per-band energy of the last second against the body would catch the Breeze tail collapse), muffled or thinning timbre over a long take (spectral centroid or high-band energy over time), short identity switches inside one take (windowed speaker similarity), take-to-take shifts in loudness and speaking rate for the same voice (per-voice rate and level against that voice's median), spontaneous background sound (VAD or music detection on the non-speech parts), and vocal-event text that is skipped or voiced as words.
- AJ's loss of half the words on two lines of about 60 words matches the skip class (a run of 10 or more deleted words). Breeze's maintainers say longer complete passages are better for consistency, and the long-form paper says failures grow with length, so the two goals pull against each other. The data favor keeping each take well under the 120 s ceiling and splitting only the outlier lines.
- The reference-clip preparation on BreezeBlue's hosted platform (denoise, exact-transcript excerpt of at most 30 s, -18 LUFS) is a cheap fix that applies to every take of a voice. It could reduce per-voice level and timbre variation at the source.
- Because Breeze's English vocal events are written in parentheses, any parenthetical text left in a script line may be read as an event cue or skipped. That is a text-prep check worth adding.

### Gaps
- No public WER, skip or hallucination rates for Breeze TTS 2 in English long-form use. The only quantified Breeze defects are from one 26-seed Mandarin sweep.
- No reports found of Breeze reading the acting direction aloud, speeding up within a take, or adding long internal silences. Absence of reports is not evidence of absence. The model is only 2.5 months old.
- The r/LocalLLaMA "initial impressions" thread on Breeze TTS 2 was not retrieved.

## 5. What does practice say about generating N candidates per line and selecting one, and about feeding defects back into the text? What line length keeps failure rates low?

### Takeaway
Practice converges on 2 to 3 tries, not large N: ElevenLabs regenerates up to 2 times, epub2tts tries twice, Chatterbox-Extended runs 3 candidates with up to 3 attempts each and keeps the shortest passing take. Research shows best-of-N lowers WER only modestly (2.06% to 1.72% at the best single verifier), costs grow linearly, and some failures persist across seeds, so the reported cures for a stubborn line are a text change (respell the flagged word, split the sentence) or an alignment-aware rollback. Tools cap chunks at 250 to 500 characters (IndexTTS: 120 text tokens), while Breeze's maintainers advise complete passages under about 120 s of audio.

### Cited Findings
- Candidate counts and selection in practice: Chatterbox-Extended 3 candidates x 3 attempts, shortest passing take wins, longest transcript as fallback. [Chatter.py](https://raw.githubusercontent.com/petermg/Chatterbox-TTS-Extended/main/Chatter.py). ElevenLabs Auto-Regenerate up to two regenerations. [ElevenLabs help](https://help.elevenlabs.io/hc/en-us/articles/30204568681745-What-is-Auto-Regenerate). epub2tts 2 attempts, keeps the last. [epub2tts.py](https://raw.githubusercontent.com/aedocw/epub2tts/main/epub2tts.py). Pandrator best NISQA MOS of N or a threshold. [Pandrator via search](https://git.tdem.in/lukaszliniewicz/Pandrator)
- An XTTS-v2 user's view of retrying: "even if a gen is bad, the sheer speed means I can dice-roll out of bad gens quicker". [r/StableDiffusion via search](https://redlib.ssps.io/r/StableDiffusion/comments/1l5nq43/chatterbox_tts_fork_huge_update_3x_speed_increase)
- The long-form paper says best-of-N selection by the lowest external-ASR WER costs linearly in N "and may not fix failures that persist across seeds", and did not evaluate it as a baseline. [arXiv HTML](https://arxiv.org/html/2609.16989)
- Best-of-N gains depend on the ASR family. Best single verifier 2.06% to 1.72% WER, cross-family ensembles 1.61% at N = 10. [arXiv 2607.08256](https://arxiv.org/abs/2607.08256)
- Breeze defects are seed-dependent and appear about once per 26 seeds each in one sweep, and the failing seed differs between machines. [breeze-tts issue 14](https://github.com/breezeblue-ai/breeze-tts/issues/14)
- Feeding defects back into text: the VoxCPM2 gate respells only the mismatched words (pinyin or CMU tags) for its second take. [ai-muninn](https://ai-muninn.com/en/blog/voxcpm2-news-shorts-narration-2080ti). AllTalk's fix for "token length issues" is smaller chunks. [AllTalk wiki](https://github.com/erew123/alltalk_tts/wiki/TTS-Generator). Chatterbox-Extended splits long sentences at `; : - ,` then space. [Chatter.py](https://raw.githubusercontent.com/petermg/Chatterbox-TTS-Extended/main/Chatter.py). Google Play fixes homographs by respelling the audio text. [Google Books Partner help](https://support.google.com/books/partner/answer/14182676)
- Chunk limits used by tools: AllTalk under 250 characters. [AllTalk wiki](https://github.com/erew123/alltalk_tts/wiki/TTS-Generator). Chatterbox-Extended 300 characters, minimum 20. [Chatter.py](https://raw.githubusercontent.com/petermg/Chatterbox-TTS-Extended/main/Chatter.py). Alexandria groups script entries up to 500 characters. [Alexandria](https://github.com/Finrandojin/alexandria-audiobook). Orpheus-FastAPI splits above 1,000 characters. [Orpheus-FastAPI](https://github.com/Lex-au/Orpheus-FastAPI). IndexTTS2 120 text tokens per segment, 80 to 200 recommended. [webui.py](https://raw.githubusercontent.com/index-tts/index-tts/main/webui.py). epub2tts one sentence per call. [epub2tts.py](https://raw.githubusercontent.com/aedocw/epub2tts/main/epub2tts.py)
- Breeze: keep complete passages together within about 120 s of audio and split only at paragraph or sentence boundaries. [breeze-tts issue 25](https://github.com/breezeblue-ai/breeze-tts/issues/25). The cpp port's experimental quantizations degrade past about 45 s. [HoppouAI](https://huggingface.co/HoppouAI/Breeze-TTS-2.cpp)
- Short inputs fail too: chatterbox-Audiobook lists "short sentences may occasionally cause problems", and Chatterbox-Extended merges sentences under 20 characters. [chatterbox-Audiobook](https://github.com/psdwizzard/chatterbox-Audiobook), [Chatter.py](https://raw.githubusercontent.com/petermg/Chatterbox-TTS-Extended/main/Chatter.py)

### Inferences
- For AJ's loop: two seed rounds is in line with practice. A third step that changes the text is better supported than more seeds: split a line over a word threshold at its strongest clause boundary and render the halves as separate takes joined with a short pause, or respell the word Parakeet missed. The 60-word lines that lost half their words are the case for a length-triggered split, which can be applied before the first take as well as after a flag.
- A cheap selection score from the sources, for when several takes pass: fewest diff words first, then shortest duration (Chatterbox-Extended), then the closest speaking rate to the voice's median.
- Very short lines (a word or two, "Yes.") are a known weak spot for these models. Merging them is not possible across speakers in a screenplay, so a length guard with looser bounds or several candidates for short lines is the practical option.

### Gaps
- No source gives a failure rate per line length for Breeze, or for any model at the sentence scale (20 to 80 words) that matters here. The long-form paper's bins start at "under 500 words".
- No measurement found of how often a text change fixes a line that two seed rounds did not.

## 6. What text-side preparation prevents defects?

### Takeaway
Tools normalize text with rules first and an LLM second: expand numbers, dates, Roman numerals and abbreviations, strip footnote markers, brackets and reference numbers, straighten quotes, map dashes and semicolons to commas, and fix initialisms like "J.R.R.". Context-dependent cases (a Roman numeral as a king or a chapter, "Dr." versus "St.", homographs) go to an LLM or a hand lexicon. The same normalization has to be applied to both sides of the ASR diff, because Orion QC and AllTalk found that numbers, punctuation and homophones cause most false flags.

### Cited Findings
- PolyNorm (Apple, arXiv 2511.03080, 2025-11) does few-shot LLM text normalization for TTS across 27 categories including Roman numerals. [arXiv](https://arxiv.org/html/2511.03080v1)
- ElevenLabs advises putting normalization rules in the prompt when an LLM writes TTS text, such as "XIV" as "fourteen" or "the fourteenth" by context, and "Dr." as "Doctor" while keeping "St. Patrick", or normalizing with regular expressions first. [ElevenLabs normalization docs](https://docs.cdntest.elevenlabs.io/best-practices/prompting/normalization)
- Ambiguity and ordering: "01/02/2025" depends on locale. [Inworld guide](https://runware.ai/docs/models/inworld-tts-2/guides/llm-system-prompts). Rule order matters, for example acronym expansion before time parsing breaks a later match. [SwiftCase](https://swiftcase.co.uk/2026/01/19/tts-text-normalization-natural-ai-speech/). Rime normalizes numbers, dates, currency and measurements and treats acronyms separately. [Rime docs](https://docs.rime.ai/docs/text-normalization.md). Regex normalization adds negligible latency, LLM normalization adds latency for a marginal gain. [SimbaVoice](https://simbavoice.ai/resources/how-tts-models-handle-numbers-dates-and-acronyms)
- Tool rules: Chatterbox-Extended lowercases, fixes "J.R.R.", removes reference numbers and maps sound words. [Chatter.py](https://raw.githubusercontent.com/petermg/Chatterbox-TTS-Extended/main/Chatter.py). epub2tts maps dashes, semicolons and colons to commas, straightens quotes, expands "&", removes brackets and drops footnote links and page breaks. [epub2tts.py](https://raw.githubusercontent.com/aedocw/epub2tts/main/epub2tts.py). abogen uses an LLM for apostrophes and contractions and spaCy for sentence boundaries around abbreviations. [abogen](https://github.com/denizsafak/abogen). audiobook-creator normalizes special characters and fixes unterminated quotes and broken lines. [audiobook-creator](https://github.com/prakharsr/audiobook-creator). Alexandria fixes mojibake and writes non-verbal sounds as pronounceable text ("Ahh!") rather than bracket tags. [Alexandria](https://github.com/Finrandojin/alexandria-audiobook)
- Lexicons: ElevenLabs suggests terms needing rules and applies the first matching dictionary rule. [ElevenLabs docs](https://elevenlabs.io/docs/eleven-creative/products/audiobooks). Google takes IPA or a recorded example and plays every occurrence. [Google Books Partner help](https://support.google.com/books/partner/answer/14182676). IndexTTS-2.5 accepts CMU phonemes inline. [IndexTTS](https://github.com/index-tts/index-tts)
- ASR-side normalization: Orion QC's stated challenge was not flagging a date written differently in audio and text. [Bertelsmann](https://tech.bertelsmann.com/en/blog/articles/orion-qc). Whisper `initial_prompt` with the line's names and numbers removed most false flags in the VoxCPM2 gate. [ai-muninn](https://ai-muninn.com/en/blog/voxcpm2-news-shorts-narration-2080ti)
- Breeze specifics: English vocal events go inline in parentheses, the instruction language should match the text, and the reference transcript must match its audio exactly. [Model card](https://huggingface.co/BreezeBlue/Breeze-TTS-2). A misaligned reference transcript contributed to a collapse case. [breeze-tts issue 14](https://github.com/breezeblue-ai/breeze-tts/issues/14)

### Inferences
- Checks AJ could add to the script text before rendering: no digits, Roman numerals or symbols left in a spoken line, no parentheses (Breeze may treat them as vocal events), no italics markers or ALL-CAPS words without a decision on emphasis, no stray quote marks, and every capitalized name either in the say-as map or confirmed common. Since a Claude pass already writes the script, these can be a validator that sends offending lines back to the pass, which is an automatic fix.
- The say-as map could be seeded automatically the way ElevenLabs does it: collect proper nouns from the character bible and chapter, and flag those that Parakeet misrecognizes across several takes.

### Gaps
- No source measures how much each normalization rule reduces TTS errors for an LLM-based model. All guidance is qualitative.
- How Breeze reads italics, capitals or unusual punctuation is undocumented.

## 7. What do listeners of multi-voice productions notice that a per-take check misses, and are there LLM-based script checks?

### Takeaway
Proofers and the AI-narration checklists add cross-take and script-level defects: a character's voice, tone or accent drifting between takes or chapters, inconsistent pronunciation of the same name, pauses that ignore context (none after a heading, uniform gaps between speakers), retake seams, and dialogue given to the wrong speaker or narration left in a character's line. Alexandria's optional second LLM pass is the clearest working script check (it pulls misattributed dialogue out of narrator entries and strips "he said" tags from dialogue). For an independent attribution check, ModernBookNLP reports 94.5% quote-attribution accuracy on PDNC.

### Cited Findings
- Proofers listen for character voice consistency (voice, tone, accent) and inconsistent pronunciation. [Pozotron blog](https://blog.pozotron.com/what-does-an-audiobook-proofer-do). ACX requires consistent levels, tone, noise, spacing and pronunciation across the book. [ACX help](https://help.acx.com/s/article/acx-audio-submission-requirements). AI checklists add cross-chapter drift in voice, accent, speed, style, loudness and room tone, edit seams, overdone emphasis and broken dialogue. [Narration Box](https://narrationbox.com/blog/acx-rejection-checklist-ai-narrated-audiobooks)
- Breeze segments with the same reference and seed differed audibly in timbre and volume. [breeze-tts issue 25](https://github.com/breezeblue-ai/breeze-tts/issues/25). Windowed speaker similarity reveals identity switches inside long generations. [arXiv 2609.16989](https://arxiv.org/html/2609.16989)
- Pause practice between lines: Alexandria 500 ms between different speakers and 250 ms for the same speaker. [Alexandria](https://github.com/Finrandojin/alexandria-audiobook). Breeze maintainers 0.2 to 0.3 s between segments. [breeze-tts issue 25](https://github.com/breezeblue-ai/breeze-tts/issues/25). epub2tts 0.6 s between sentences and 2 s at chapter end. [epub2tts.py](https://raw.githubusercontent.com/aedocw/epub2tts/main/epub2tts.py). chatterbox-Audiobook 0.1 s per line break. [chatterbox-Audiobook](https://github.com/psdwizzard/chatterbox-Audiobook). Orion QC flags silences over 3 s. [Bertelsmann](https://tech.bertelsmann.com/en/blog/articles/orion-qc)
- Script-level LLM checks: Alexandria's review pass strips attribution tags from dialogue, splits narration mixed into character entries, extracts misattributed dialogue from narrator entries, merges short consecutive narrator entries and corrects invalid instruct fields. - Quote attribution accuracy: ModernBookNLP's joint scoring reaches 94.5% on PDNC (35,000+ quotes from 22 novels) and runs about 20 times faster than standard methods and over 1,000 times faster than LLM approaches (arXiv 2608.02359, 2026-08-03). ### Inferences
- A script-versus-source check catches what no take check can: if the screenplay pass drops or duplicates a sentence of the chapter, every take can pass and the chapter is still wrong. Aligning the concatenated script text (narration and dialogue, without directions) to the chapter text with a word diff, as Orion QC does for audio, flags dropped or repeated spans for a re-run of the script pass. The fix is automatic.
- Speaker attribution can be cross-checked without a second Claude call by running ModernBookNLP (or BookNLP) on the source chapter and comparing its speaker per quote with the script's speaker. Disagreements on explicit quotes are likely script errors, so they can go back to the script pass with the disagreement as a note.
- Cross-take voice consistency can be automated per character: embed every take of a character, compare with the character's cast clip and with that character's median, and retake outliers. The same median gives speaking rate and loudness outliers, which addresses the Breeze issue 25 reports.
- Pause length by context (speaker change versus same speaker, end of paragraph, scene break) is a script-driven rule that the join can apply, with Alexandria's 500/250 ms as a starting point.

### Gaps
- No listener study found that ranks which multi-voice defects bother listeners most.
- No public LLM check found that verifies a screenplay against its source chapter for dropped or repeated text. Alexandria's review pass does not cover it.
- PDNC accuracy is for 19th and 20th century novels. Accuracy on web-serial fantasy prose is untested.
